# Model：PROJECT_MODEL.md 规则

`PROJECT_MODEL.md` 是人类重新进入项目时的第一张“认知地图”。目标不是全面，而是**决策充分压缩**：在尽量短的情况下，保留足以判断下一步的目标、结构、机制、边界和控制点。

## 必须回答

1. 为什么做，成功状态是什么？
2. 理解项目必须知道哪些核心对象/概念？
3. 这些对象怎样形成关键流程/机制？
4. 最终能力或正式产出是什么？
5. 当前 scope 与明确 non-goals 是什么？
6. 哪些**类别**的高影响事项必须由人做取舍？（具体当前待拍板问题放 State）

## 写法

- 优先使用 2–5 句话总目标 + 少量编号流程。
- 同一级内容保持同一抽象层级，不混合“业务能力 / 文件修改 / 技术细节 / 待办”。
- 流程优先写“对象/触发 → 动作/机制 → 结果/用途”。
- 不写目录清单、文件历史、任务日志、实现细节。
- 不为了简短压掉关键假设、风险或未决边界。

## 更新条件

只有稳定语义变化才更新：目标、核心对象/机制、能力定义、scope/non-goal、Human Control Points。

普通实现进度进入 `PROJECT_STATE.md`；原因进入 `notes/`；依赖进入 `ARCHITECTURE.md`。
